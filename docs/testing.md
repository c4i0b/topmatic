# Testing

Layers, cheap to expensive (coverage without overlap — a behavior is pinned
at the cheapest layer that can see it, and nowhere else):

1. **Unit** — pure domain logic, sibling `tests.rs`/`*_tests.rs` files next
   to the module (`src/domain/*`, `src/tui/app/app_tests.rs`, ...). No IO.
2. **Integration** — `tests/runner_integration.rs`: real runner code
   against stub topgrade binaries in tempdirs. Offline.
3. **Live** — `tests/systemd_integration.rs`, `#[ignore]`-marked and run
   only via `just test-live` (the container bridged to the host user
   systemd session). This is real `systemctl --user` output feeding the
   timestamp parser; it exists because the parser's job is exactly to eat
   what real systemd prints.

The default suite (`just test`) is offline and hermetic: it runs in the
ephemeral container with no network and no real systemd. Tests never touch
the real user systemd manager or the real topgrade.

## Fixtures

`tests/fixtures/` holds recordings of real tool output, regenerated by the
host-side `just fixture` / `just fixture-disable` recipes:

| Fixture | Durability class | Policy |
|---|---|---|
| `topgrade_help.txt` | moving snapshot (step list changes per topgrade release) | shape assertions; regenerate on topgrade bumps (`just fixture`) and review the diff before adapting presets |
| `topgrade_disable_error.txt` | recorded error shape | exact assertion; must be regenerated with the SAME topgrade version as the help fixture |

Refresh trigger is a topgrade version bump, not the calendar. Config keys
must be verified against the real binary: topgrade's step-exclusion key is
`disable`; an invented `ignore` was once silently rejected and the run kept
failing — the parse error listing the valid schema was the fixture.
